# 模型实验与数据治理方案

## 目标与边界

目标应表述为：从有授权、可追溯的照片中提示**可见表型候选**，供有经验的饲养者或繁育者复核。不能把单张图片的颜色分类包装成隐性基因携带型检测，也不能把预测当作基因型或繁育结论。

## 数据记录

每张图片至少保存：原始文件哈希、来源 URL/贡献者、图片使用许可、蛇只唯一 ID、物种确认、拍摄日期/年龄阶段、视角与光照、标签值（阳性 / 阴性 / 未知）、标签证据（繁育谱系、遗传检测或外观描述）、标注者、复核者和修改历史。可见表现与基因型证据应分开字段记录。

- 仅在许可允许的范围内保存与公开图片。
- 空白或证据不足的字段记为 `unknown`；不能推断成阴性。
- 对不同术语/组合维护显式本体与同义词表；组合 morph 不等于单个基因标签。
- 不把商家自述或网页图注未经核验地提升为 ground truth。

## 训练与评估

1. 先建立小规模的固定验证集，按**个体 ID**分组；同一条蛇、连拍、同图裁切和增强版本不得跨训练/测试集。
2. 预处理只在样本训练划分确定后应用，增广仅用于训练集。先比较原图与合理色彩/白平衡方案；避免会改变颜色判别语义的增强。
3. 多标签任务使用逐标签 sigmoid logits 与 binary cross-entropy（可对已标注字段做 mask）。只有样本充分时，再评估预训练视觉编码器微调；以简单基线作对照。
4. 报告每类支持数、逐类 precision/recall/F1、macro-F1、average precision（AP；当前实现不称为梯形 PR-AUC）、混淆/共现分析及按蛇只 ID 整体重采样得到的 95% bootstrap 区间；按个体留出测试。测试个体过少时区间会很不稳定，不能据此宣称广泛泛化。类别样本不足时明确标注“不可评估”。

bootstrap 区间应同时报告有效重采样次数。逐类指标只使用该指标在重采样中有定义的轮次；macro-F1 采用固定完整类别估计对象，仅保留每个待评类别都同时抽到阳性和阴性样本的轮次。两者均为有条件的百分位区间，需明确其筛选规则和有效次数。
5. 在独立验证集上确定逐类阈值并校准概率。低证据、低置信度或分布外照片须拒识并提示人工复核，不把 softmax/sigmoid 数值直接称为可靠置信度。
6. 由繁育者/专家盲评候选标签，记录分歧。对新个体、不同年龄、背景和光照做外部验证。

训练器按蛇只 ID 做确定性 70/15/15 分组划分，并尝试在保持分区大小不变的前提下，让更多类别满足支持数门槛。每个类别在训练集至少要有 5 个阳性和 5 个明确阴性个体，在验证集和测试集各至少有 3 个阳性和 3 个明确阴性个体。因此 30 条蛇不可能满足验证/测试分区容量；按当前 Python `round` 分区规则，容量上的最低值是 39 条（27/6/6）。39 只是数学下限，不代表统计上足够。训练器会在导入 PyTorch 前打印/报告类别阳性、明确阴性数量和分区可行性；同一条蛇对同一类别出现相互矛盾的明确标签时会拒绝训练。全局数量充足也不保证每个类别可训练，仍须查看优化后分区诊断。

## 当前数据门槛

原工作簿引用 figure1–figure101，但图片目录仅有 figure1–figure21。17 个标签中一个没有阳性例子，其余标签每类仅 1–7 个工作簿阳性记录；部分单元格为空，且缺少来源、个体与遗传证据。其中“White Wall／白墙”应归为可见外观描述，不是基因座，因此这 17 列不能直接说成 17 个基因标签。补充 DOCX 有 38 个图像实例，但它们是形态参考图，媒体许可未记录，也没有个体身份和可验证基因型，因此不能计入监督训练集。当前不应报告模型准确率。后续任务应依照规范化后的遗传性状定义，并保留原工作簿列作溯源，而不是把全部历史列直接当作分类类别。

## 旧 MATLAB 原型审计

旧 Live Script 指向不存在的 `猪鼻蛇基因分析.xlsx`，列名也与实际工作簿不一致；把标签表按单元格转为分类变量的写法不符合多标签建模；增强在划分之前执行；`denoiseplus.m` 为空；末尾引用了未定义的 `testData`。其嵌入输出还显示表格路径错误。因此，履历或比赛介绍应先将旧原型描述为课程探索，不将其写成已完成且验证的遗传识别器。
